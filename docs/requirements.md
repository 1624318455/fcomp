# FComp - 文件比对工具需求文档

## 1. 项目概述

### 1.1 项目背景

FComp（File Compare）是一款基于 Web 的文本文件比对工具，旨在帮助用户快速比较两个文本文件的差异，并以直观的方式高亮显示差异内容。该工具采用纯前端静态实现，无需服务器支持，所有比对逻辑在浏览器中完成，确保用户数据隐私安全。

### 1.2 项目定位

- **产品类型**：PC 端 Web 工具类应用
- **目标用户**：开发者、内容编辑、文档工作者、技术写作者
- **核心价值**：快速、简单、私密地比对文本文件差异

### 1.3 竞品分析总结

通过对现有主流比对工具的分析，明确以下核心特性：

| 特性 | 说明 |
|------|------|
| 侧边比对视图 | 左右双面板并排显示，高效对比 |
| 差异高亮 | 颜色区分新增（绿）、删除（红）、修改（黄） |
| 多种输入方式 | 支持文件上传和文本粘贴 |
| 同步滚动 | 左右面板滚动同步，便于定位差异 |
| 纯客户端处理 | 所有数据在浏览器中处理，不上传服务器 |

## 2. 功能需求

### 2.1 双面板布局

**功能描述**：

- 页面采用左右对称的双面板布局
- 左侧面板为「原始文件」（Source）
- 右侧面板为「比较文件」（Target）
- 两面板宽度相等，占据页面主要区域

**UI 结构要求**：

```
┌─────────────────────────────────────────────────────────┐
│                      Header                              │
├─────────────────────────┬───────────────────────────────┤
│                         │                                │
│    原始文件面板          │      比较文件面板              │
│    (Source Panel)       │      (Target Panel)           │
│                         │                                │
│                         │                                │
├─────────────────────────┴───────────────────────────────┤
│                      Footer                              │
└─────────────────────────────────────────────────────────┘
```

### 2.2 文件上传功能

**功能描述**：

- 每个面板顶部提供文件上传按钮
- 点击按钮打开系统文件选择器
- 支持一次选择单个文件

**支持的格式**：

| 格式类型 | 扩展名 |
|----------|--------|
| 纯文本 | .txt |
| JavaScript | .js, .jsx |
| TypeScript | .ts, .tsx |
| JSON | .json |
| HTML | .html, .htm |
| CSS | .css, .scss, .sass, .less |
| Markdown | .md, .markdown |
| XML | .xml |
| YAML | .yaml, .yml |
| SQL | .sql |
| Shell 脚本 | .sh, .bash |
| 其他文本 | .log, .conf, .ini, .properties |

**技术要求**：

- 使用 HTML5 File API 读取文件
- 文件大小限制：10MB（单文件）
- 字符编码：自动识别 UTF-8，兼容 GBK
- 上传成功后自动填充对应面板内容

### 2.3 文本粘贴功能

**功能描述**：

- 每个面板提供文本输入区域
- 用户可直接在输入框中粘贴文本内容
- 粘贴后内容实时显示在面板中

**交互要求**：

- 面板获取焦点后即可粘贴
- 支持 Ctrl+V / Cmd+V 快捷键粘贴
- 粘贴后自动检测语言类型（可选）

### 2.4 差异比对与高亮显示

**功能描述**：

- 点击「开始比对」按钮后执行差异分析
- 使用行级 diff 算法（diffLines）进行比对
- 比对完成后高亮显示差异区域

**差异类型定义**：

| 类型 | 定义 | 颜色 |
|------|------|------|
| 新增（Added） | 右侧文件中新增的内容 | 绿色背景 (#e6ffed) |
| 删除（Removed） | 左侧文件中删除的内容 | 红色背景 (#ffebe9) |
| 修改（Modified） | 两边都有但内容不同 | 黄色背景 (#fff5b1) |
| 相同（Unchanged） | 两边相同的内容 | 无高亮 |

**显示要求**：

- 每行显示行号（便于定位）
- 差异行使用背景色高亮
- 单词级别的差异在行内使用不同颜色标注
- 差异区域使用颜色边框标识

### 2.5 同步滚动功能

**功能描述**：

- 左右面板滚动位置保持同步
- 用户滚动任一面板，另一面板自动跟随
- 便于对照查看对应的差异区域

**技术要求**：

- 使用 JavaScript 事件监听实现
- 滚动比例保持一致
- 可通过设置开关启用/禁用同步滚动

### 2.6 清空/重置功能

**功能描述**：

- 提供「清空全部」按钮，清除两侧内容
- 单独提供「清空左侧」「清空右侧」按钮
- 重置后界面恢复初始状态

**交互要求**：

- 清空前如有内容，弹出确认提示
- 清空后差异高亮区域同步清除
- 清空后文件上传按钮恢复可点击状态

### 2.7 文件名显示

**功能描述**：

- 面板顶部显示已加载文件的名称
- 未加载文件时显示默认占位文字
- 支持拖拽文件到面板自动加载（可选）

## 3. 非功能需求

### 3.1 用户界面

**设计原则**：

- 简洁直观，减少学习成本
- 采用浅色主题，清晰易读
- 重要操作按钮突出显示

**配色方案**：

| 用途 | 颜色 |
|------|------|
| 主色调 | #2563eb（蓝色） |
| 新增背景 | #e6ffed（浅绿） |
| 删除背景 | #ffebe9（浅红） |
| 修改背景 | #fff5b1（浅黄） |
| 边框颜色 | #e5e7eb（灰色） |
| 文字颜色 | #1f2937（深灰） |

**布局要求**：

- 页面最小宽度：1024px
- 面板最小高度：400px
- 按钮大小：高度 36px， padding 8px 16px
- 字体：默认使用系统字体（-apple-system, BlinkMacSystemFont, Segoe UI, Roboto）

### 3.2 响应式布局

**断点设计**：

| 断点 | 宽度 | 布局变化 |
|------|------|----------|
| Desktop | >= 1200px | 双面板等宽并排 |
| Laptop | 1024px - 1199px | 双面板等宽并排 |
| Tablet | < 1024px | 提示使用 PC 端或堆叠布局 |

**适配说明**：

- 主要适配 PC 端桌面显示器
- 在笔记本屏幕（1366x768）上正常显示
- 移动端提示使用 PC 设备访问

### 3.3 性能要求

| 指标 | 要求 |
|------|------|
| 首次加载 | < 2 秒 |
| 文件解析（10MB以内） | < 1 秒 |
| 比对执行（10000行以内） | < 3 秒 |
| 滚动流畅度 | 60 FPS |

### 3.4 兼容性

**浏览器支持**：

- Chrome 90+
- Firefox 88+
- Safari 14+
- Edge 90+

**技术限制**：

- 不支持 IE 浏览器
- 不支持移动端浏览器（提示使用 PC）

### 3.5 安全与隐私

- 所有文件处理在浏览器本地完成
- 不向服务器发送任何文件数据
- 刷新页面后数据自动清除
- 无需用户注册登录

## 5. 技术实现参考

### 5.1 核心依赖

推荐使用 `jsdiff` 库实现差异比对：

```bash
npm install diff
```

主要 API：

- `diff.diffLines(oldStr, newStr)` - 行级差异比对
- `diff.diffWords(oldStr, newStr)` - 单词级差异比对
- `diff.diffChars(oldStr, newStr)` - 字符级差异比对

### 5.2 项目结构建议

```
fcomp/
├── index.html          # 主页面
├── css/
│   └── styles.css      # 样式文件
├── js/
│   ├── main.js         # 主逻辑
│   └── diff.js         # 比对模块（CDN引入）
└── assets/
    └── icons/          # 图标资源
```

### 5.3 纯静态实现方案

由于需求明确「前端纯静态实现」，建议：

- 使用单个 HTML 文件或简单项目结构
- 通过 CDN 引入 jsdiff 库
- 所有逻辑在客户端执行
- 无需后端服务器
